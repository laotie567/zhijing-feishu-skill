# 部署细节参考

> agent 部署遇阻时参考本文。日常不需要读。

## 交付物边界

- **`zhijing-deploy/`（以及等价的 zip / tar.gz 包）是给客户的纯净包**：只含建表脚本、skill 模板、备选工具、业务数据（`data/*.json`，无任何租户 ID）与安装脚本，**零凭证、零租户标识**，可直接交给客户。
- **`交付文档/`、`.zcode/plans/` 属内部工作产物**，不随客户包分发：
  - `交付文档/` 含原项目租户的实测快照（Base/Table/Field ID、门店 record_id）与内部实施记录，是给项目内部运维/验收用的；
  - `.zcode/plans/` 是内部规划稿，含未决问题与未实现步骤（如 `+workflow-create`），交付客户会造成预期偏差。
- **若需整目录交付**，请先移走 `.zcode/plans/` 等内部规划稿，并确认随附的交付文档已按「原租户快照」标注（客户环境 ID 以本地 `ids.json` 为准）。

## 多维表格结构（build_bitable.py 创建的）

6 张表，均已在本机验证可用：

| 表 | 用途 | 关键字段 |
|----|------|---------|
| 门店主表 | 5家门店基础信息 | 门店名称/城市/占股/合同签订日/开业目标日期 |
| 筹备任务表（核心） | 250条门店专属任务 | 任务名称/筹备阶段/责任方/任务状态/所属门店(关联) |
| 交付物验收表 | 交付物/验收节点 | 交付物名称/验收状态/附件 |
| 阶段里程碑表 | 关键节点 | 里程碑名称/计划完成日期/状态 |
| 岗位表 | 7个标准岗位 | 岗位名称/所属公司 |
| 人员表 | 责任人 | 飞书账号/所属岗位 |

**仪表盘与工作流**：脚本会创建 `PMO全局进度看板`（6 个组件：筹备任务总数/任务状态分布/各阶段任务数/责任方分工占比/催办状态分布/各岗位任务负载），属增强项——失败只警告不中断部署。**自动化工作流不由脚本创建**，需按《附录3》手工配置（`+workflow-create` 建出的是禁用态，且需先指派「责任人」才有意义）。

## 公式字段（自动计算）

- **催办状态**（任务表）：IFS 判定 已完成/已逾期/今日到期/即将到期/进行中
- **逾期天数**（任务表）：已逾期且未完成的天数
- **距开业天数**（门店表）：开业目标日期倒计时
- **总体进度**（门店表）：已完成任务数/总任务数（跨表回算）

## 任务展开逻辑

54条模板任务 → 按适用门店展开为 250 条：
- "全部"(48条) → 5店各1条 = 240
- "广元/绵阳"(2条) → 2店 = 4
- "西博城"(2条) → 2
- "明逸/广元/绵阳"(1条管家) → 3
- "有采购合同门店"(1条) → 怡嘉 = 1

每条通过「所属门店」link 字段双向关联到门店。

## 常见部署错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `9499 Bad Request` | lark-cli 命令参数格式错 | 检查 build_bitable.py 里 filter 格式 |
| `99991672 Access denied` | lark-cli 未登录或无权限 | `lark-cli auth login` 重新登录 |
| 公式编译失败 | 表达式语法错 | 距到期天数等公式用 ISBLANK 兜底，日期相等用 TEXT 转换 |
| select 选项 not_found | 写入的选项名与表配置不符 | 优先级用全名（P0紧急 而非 P0） |

## lark-cli 关键命令速查

```bash
# 查门店
lark-cli base +record-list --base-token <BT> --table-id <stores> --as user --limit 10

# 按门店+关键词查任务（用 record_id 精确匹配所属门店）
lark-cli base +record-list --base-token <BT> --table-id <tasks> --as user \
  --filter-json '{"logic":"and","conditions":[["所属门店","==","<store_rec_id>"],["任务名称","intersects","装修"]]}'

# 更新任务
lark-cli base +record-batch-update --base-token <BT> --table-id <tasks> --as user \
  --json '{"record_id_list":["recXXX"],"patch":{"任务状态":"已完成","实际完成日期":"2026-07-25"}}'
```
